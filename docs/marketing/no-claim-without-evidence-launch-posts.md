## LinkedIn

I turned my recent notes on AI evals, extraction errors, review workflows, evidence, and release gates into a practical ebook:

**No Claim Without Evidence: How to Build AI Systems You Can Verify**

The core idea is simple:

AI systems should not be trusted because the output looks clean.

They should be trusted because the claim can be traced to evidence, tested against requirements, reviewed when uncertain, and blocked before release when the system cannot justify itself.

The book covers:

- why premature confidence is the real AI product bug
- how to separate extraction from inference
- how to design field-level evidence records
- how to evaluate the pipeline, not just the model
- how to use review rules, error taxonomies, action traces, and release gates
- how to make AI outputs auditable enough for real products

The running example is an airline-ticket extraction workflow where the model invents a terminal that was not present in the source document.

That one small mistake is the whole problem in miniature.
